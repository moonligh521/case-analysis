# 案情分析

把案情材料走完解析、争议焦点、法条匹配和报告，并让人在关键步骤确认。

本仓库是 [moonligh](https://moonligh.cn/) 的个人开源项目，采用 [Apache-2.0](LICENSE) 许可证。

## 概述

一份卷宗里可以同时有 PDF、Word 和图片。本项目把分析分成四个阶段：材料解析、争议焦点、法条匹配、报告生成。每个阶段都可以确认、修订或回滚。

解析同时使用本地文本提取和视觉 OCR。分块采用语义边界和跨页重叠窗口，并保留页码与块坐标，报告里的事实句能回到原文。法条检索分成两路：向量检索负责语义相近的表述，BM25 负责法条原文里的术语；两路合并去重，再经 Rerank 进入生成。检索条件来自案情和争议焦点。

风险提示和证据链放在独立线程池里并行生成，并用版本号避免旧结果覆盖新结果。生成之后核对事实有没有原文、主体有没有混淆、引用的法条是否存在，有缺陷就回到对应阶段重试。示例案情使用虚构或公开文本。

## 状态

当前提交的是仓库骨架和社区文件。包名、目录和文档已经按开源仓库放好，业务代码和构建文件尚未写入。下面的功能范围是这个仓库要完成的事，还不是已经可运行的能力。

## 功能范围

- 按材料解析、争议焦点、法条匹配、报告生成四段推进，并支持确认、修订和回滚
- 用本地文本提取和视觉 OCR 解析 PDF、Word 和图片
- 语义分块保留页码和块坐标，跨页使用重叠窗口
- 围绕案情和争议焦点做向量检索与 BM25 检索，合并去重后再 Rerank
- 用独立线程池并行生成风险提示和证据链，并用版本号避免旧结果覆盖新结果
- 核对事实出处、主体是否混淆、法条是否存在，有缺陷则回到对应阶段重试

## 技术选择

五个仓库使用同一套运行时，模型接入使用 Spring AI。

- JDK 21
- Spring Boot 4.1.1
- Spring AI 2.0.1
- MySQL 8.0.46
- Redis 8.2.10
- RocketMQ 5.5.1，Java 客户端使用 rocketmq-spring 2.3.6

在本仓库中，Spring AI 负责分阶段生成、检索后的上下文和引用核对。MySQL 按版本保存阶段结果和报告。Redis 保存进行中的确认状态。风险提示和证据链在独立线程池里并行生成。

源码目录按 Maven 标准布局预留。构建文件会和第一批可运行代码一起提交。
